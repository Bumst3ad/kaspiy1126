# AGENTS.md — Smart Caspian Transit

> Читай целиком в начале КАЖДОЙ сессии, затем `docs/PROGRESS.md` и `docs/PLAN.md`. Прямой запрос человека важнее этого файла, но если он ему противоречит — скажи об этом явно. Отвечай по-русски; идентификаторы, комментарии в коде и коммиты — по-английски.

## 0. Пять правил, если забудешь всё остальное
1. **«Готово» = доказано.** Не пиши «готово/работает», пока не прошёл `npm run verify` И ты не открыл UI в браузере и не посмотрел результат глазами. Не проверял — пиши «не проверено».
2. **Один вертикальный срез за раз:** данные → логика → UI → проверка → коммит. Никаких десяти полуготовых экранов.
3. **Не трогай работающее.** Правки точечные. Не переписывай файлы целиком ради нескольких строк, не рефактори то, о чём не просили.
4. **Никаких фейков под видом реальности** (раздел 6).
5. **Токены, а не вкус** (раздел 5). Нарушение ловит `npm run check:design`.

## 1. Что это и что выигрывает
Хакатон КЦФ 2026, Трек 3, Кейс 2 «Smart Caspian Transit» — предиктивный цифровой двойник мультимодального хаба МТК «Север–Юг». Продукт: тёмная карта на весь экран + плавающие стеклянные панели. Жюри оценивает по ТЗ. Три обязательных пункта MVP:
1. **Предиктивная модель** задержек (погода на Каспии, загрузка портов, стыковка ж/д ⇄ море).
2. **Pre-clearance** (смарт-контракт или защищённый API).
3. **Единое окно логиста:** цифровой двойник груза + **углеродный след (ESG)** + **альтернативные маршруты при форс-мажоре**.

Наша фишка поверх ТЗ — **Caspian Sync-Slot**: синхронизация нитка РЖД ⇄ причал/краны ⇄ судно с учётом риска посадки на мель в ВКМСК (осадка vs глубина).
**ESG и альтернативные маршруты не опциональны.** Срез, не покрывающий пункт ТЗ, не может быть приоритетнее среза, который его покрывает.

## 2. Скоуп (времени < 24 ч; при нехватке — срезай с конца, не качество начала)
**P0 — золотой путь демо, 3 минуты. Делаем первым, доводим до блеска:**
1. Карта хаба: порты (Астрахань/Оля, Махачкала, Энзели, Амирабад), канал ВКМСК, суда, статусы.
2. Выбор судна → риск мели: осадка vs прогнозная глубина канала → алерт с временем риска.
3. «Синхронизировать слот» → панель трёх сторон (РЖД / порт / судно) → переход на Махачкалу с расчётом: время, стоимость, CO₂.
4. Карточка груза (цифровой двойник): таймлайн, ESG-сравнение маршрутов, статус pre-clearance.

**P1 — только когда P0 проходит `verify` и выглядит чисто:** DocuShield (перевод RU⇄FA⇄EN, сверка ТН ВЭД), снапшот реальной погоды, граф-модель маршрутов.
**Не делаем:** авторизация, бэкенд/БД, светлая тема, настоящий блокчейн, мобильная версия, админки.
Задача вне P0/P1 — остановись и спроси.

## 3. Стек и команды
Vite + React + Tailwind + TypeScript (strict, без `any`). Команды бери из `package.json`, не придумывай:
```
npm run dev           # dev-сервер
npm run typecheck     # tsc --noEmit
npm run lint
npm run test          # vitest, только src/domain/
npm run check:design  # scripts/check-design.mjs
npm run build
npm run verify        # typecheck && lint && test && check:design && build
```
Без явной причины не делай: новые зависимости (сначала запиши в PROGRESS.md зачем), правки конфигов сборки, удаление файлов вне задачи.
Структура: `src/styles/` (tokens.css — единственное место с hex), `src/domain/` (чистая логика + тесты), `src/data/` (seed, снапшоты, допущения), `src/ui/`, `docs/`.
Золотой путь работает **полностью офлайн**: никаких обязательных сетевых запросов, шрифты и карта с запасным вариантом локально.

## 4. Протокол долгой работы
**Старт:** прочитай PROGRESS.md и PLAN.md (нет — создай). Задача затрагивает >3 файлов — сначала план на 5–10 строк в PLAN.md с критерием «готово», потом код.
**Во время:** маленькие шаги, `typecheck` после каждого. Неясность — не повод стопориться: самое простое допущение, запись `ASSUMPTION: ...` в PROGRESS.md, дальше. Спрашивай только если заблокирован или задача вне скоупа.
**После среза:** `npm run verify` → проверка в браузере → `git commit` (один срез = один коммит, `feat(scope): ...`) → обнови PROGRESS.md: сделано / не сделано / допущения / известные баги / следующий шаг.
**Контекст:** начал путаться или повторяться — остановись, допиши PROGRESS.md так, чтобы новая сессия продолжила без потерь, и скажи об этом.
**Запрещено:** глушить проверки (`// @ts-ignore`, отключение правил линтера, ослабление `check:design`), пустые `catch`, `// TODO` вместо реализации, «успех» без логики. Упало — найди причину, не маскируй симптом.

## 5. Дизайн-система (Apple HIG, минимализм)
**Токены — единственный источник правды** (`src/styles/tokens.css` + Tailwind theme). Нужного цвета нет — добавь токен, не вставляй значение.

| Токен | Значение | Смысл |
|---|---|---|
| `bg-base` | `#0D0E11` | фон |
| `surface` | `#16171B` / `#1C1C1E` | панели |
| `hairline` | `rgba(255,255,255,0.08)` | границы |
| `accent` | `#0A84FF` | активное |
| `ok` | `#30D158` | штатно, Pre-cleared, Sync-Slot активен |
| `warn` | `#FF9F0A` | предупреждение, задержка |
| `critical` | `#FF453A` | обмеление, мель |
| `text` / `text-2` / `divider` | `#FFFFFF` / `#8E8E93` / `#3A3A3C` | текст / вторичный / разделители |

- Цвет = смысл. Зелёный/оранжевый/красный — только для статуса. Декоративного цвета нет.
- Стекло — только утилита `.glass-panel` (blur, полупрозрачный surface, hairline). Не собирай стекло заново. Blur — не более чем на 3 панелях одновременно (бьёт по FPS карты).
- Радиус панелей 16–20 px, внутренних элементов 8–12 px; сетка 4 px; максимум 2 уровня вложенных карточек.
- Шрифт: `-apple-system, BlinkMacSystemFont, "SF Pro Text", Inter, sans-serif`; `tabular-nums` для координат, осадки, времени. Иерархия размером и весом, не цветом.
- Иконки: `lucide-react`, stroke 1.5, без цветных подложек, без эмодзи.
- Анимации только функциональные (появление панели, смена статуса), 150–250 мс, ease-out. Никаких бесконечных декоративных.
- Тексты интерфейса сухие и короткие: «Осадка 4.2 м · запас 0.3 м», а не «Отлично, всё хорошо!».
- Карта: Esri World Dark Gray или аналог. Атрибуцию не удалять — сделать мелкой (`text-2`): это условие использования тайлов.

**Запрещено (ловит `check:design`):** hex вне tokens.css/tailwind-конфига; градиенты; цветные тени и свечения; сырые цвета палитры Tailwind (`text-cyan-400`, `bg-purple-*`); `animate-pulse/bounce/ping`; эмодзи в исходниках. Сомневаешься в элементе — убери его.

## 6. Данные и честность (профильное жюри поймает)
- Реальных API у нас нет. Всё симулируемое лежит в `src/data/` с полем `provenance: "real" | "synthetic" | "assumption"` и пометкой `// MOCK`. В UI есть метка «Демо-данные».
- Логика (запас под килем, конфликт слотов, углеродный след, сверка ТН ВЭД) — настоящий код в `src/domain/` поверх моков, не захардкоженные ответы. Результаты в компонентах не хардкодить.
- Запас под килем = глубина − осадка − запас безопасности (параметр). Модель глубины канала — **прозрачная физическая эвристика** (ветер → сгон → падение уровня) с интервалом неопределённости; не называй её ML без обучения. Формулы не придумывай молча — константа с источником или `ASSUMPTION`.
- Pre-clearance = подписанный манифест + hash-цепочка (SHA-256, `crypto.subtle`). Называй «ledger-ready», не «blockchain».
- Коэффициенты CO₂ — в `src/data/emissionFactors.ts` с указанием методики (GLEC / ISO 14083) и пометкой «ориентировочно».
- Названия судов — явно вымышленные («MV Demo-01»), реальных не использовать. Рандом — только с seed: демо детерминировано.
- Время хранить в UTC (ISO 8601), показывать в зоне порта; единицы подписывать в UI (м, узлы, мили).
- **Непроверенные допущения — не озвучивать как факты:** проходная осадка ВКМСК 4.2–4.5 м; падение уровня 40–60 см при сгонном ветре; потери ~$15 000/сут; «слот отдают при опоздании от 3 часов»; точка перегрузки колеи 1520/1435 (Астара или Серахс — человек проверит). Всё это только в `src/data/assumptions.ts` с `provenance: "assumption"`.
- В каждом отчёте разделяй **«реально работает»** и **«мок/симуляция»**.

## 7. DocuShield: i18n и RTL (только P1, не раньше P0)
- Строки DocuShield — через ключи `src/i18n/{ru,en,fa}.json`. Основной P0-интерфейс — русский, i18n-обвязку на него не распространяй.
- Фарси = RTL: только логические свойства (`ms-/me-/ps-/pe-/start-/end-`), не `ml-/mr-/left-/right-`; `dir` на `<html>`.
- Числа, координаты и коды ТН ВЭД внутри RTL остаются LTR (`dir="ltr"` / `unicode-bidi: isolate`). Шрифт FA — локально, без CDN.

## 8. Definition of Done
1. `npm run verify` — 0 ошибок.
2. Консоль браузера чистая (нет errors и React-warnings).
3. UI открыт во встроенном браузере на 1440×900 и 1920×1080: скриншот сверен с разделом 5, нет горизонтального скролла, золотой путь не сломан. Для DocuShield — переключись на `fa`, проверь RTL.
4. PROGRESS.md обновлён: одна строка с результатом проверки.
